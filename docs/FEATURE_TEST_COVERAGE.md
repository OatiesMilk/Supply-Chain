# Feature and test coverage matrix

Updated: 2026-11-02. PR integration baseline: `dev` commit `4bf63c6`, plus the Admin fixes and coverage additions in this PR. The original investigation and initial verification used the older `0e33fa7` working tree; those results are historical and do not validate this newer PR baseline. Final integrated validation is recorded separately below. Microsoft sign-in, identity linking and provider behavior are excluded from this coverage expansion; existing SSO tests remain unchanged.

This is a source-to-test inventory, not a claim that every feature works or that every listed suite passed in a particular environment. Record actual results, skips and target type with each run. A matching test filename, a mounted page or a successful toast does not establish the full workflow.

The existing [testing reference](testing-reference/README.md) provides a broader [endpoint catalog](testing-reference/endpoint-catalog.md), [module inventory](testing-reference/modules.md), [existing-test inventory](testing-reference/existing-tests.md) and [planned case matrix](testing-reference/test-case-matrix.md). Those documents are pinned to their stated older source revision; planned cases are not implemented tests. This document maps the current working tree. Do not regenerate the pinned reference from dirty source: [generate-test-reference.cjs](../scripts/generate-test-reference.cjs) explicitly requires a clean source/test checkout.

The newer baseline already includes the [role workflow follow-up](ROLE_WORKFLOW_FIXES_2026-10-31.md): safe central business audit values, account/record metadata preconditions, paginated operational views and equivalent transactional ordinary submission handoffs. The entries below distinguish that implemented behavior from unresolved findings in the original audit.

## Evidence levels

| Label | What it establishes | What it does not establish |
| --- | --- | --- |
| Unit | Pure validation, permission evaluation, date arithmetic, export content or cache transformation | HTTP wiring, database constraints, browser layout |
| UI double | React/JSDOM interactions with controlled API responses | Real browser sizing, native dialog focus, network or persisted database state |
| Router double | Actual middleware/handlers, sometimes isolated HTTP listeners, with database/storage/provider doubles | PostgreSQL locking/rollback or real provider delivery |
| Browser | Playwright against existing services; individual tests may still intercept responses | Every API/role path, unless explicitly asserted; real delivery of email |
| PostgreSQL opt-in | Real database behavior on the suite's designated disposable target | Deployed activation, a production audit or an external-provider outcome |

Tests under `client/tests/`, `client/src/components/__tests__/`, `client/src/utils/__tests__/` and `client/src/utils/tests/` are collected by the client package script. Server tests use `server/tests/*.test.ts`. Both use `node:test` through `tsx`, not Vitest. The separate Playwright configurations select different suites.

## Running checks safely

With the PostgreSQL opt-in variables unset, these commands run the isolated suites and TypeScript checks without resetting a database (from the repository root). Setting an opt-in variable enables its real database suite and is a separate integration decision:

```bash
npm run test:client
npm run test:server
npm run lint --workspace=client
npm run lint --workspace=server
```

For focused router/UI checks:


```bash

```

Run the added seed-identity handoffs without a real database:

```bash

```

Run actual seeded PostgreSQL checks in a runner-owned temporary cluster (from the repository root):

```bash
node scripts/test-seeded-postgres.mjs
```

The runner does not use the application's configured database. A missing PostgreSQL binary or unavailable private-cluster prerequisite is a reported validation limit, not permission to substitute the shared database.

List browser tests without executing their mutations:

```bash
cd e2e
npx playwright test --config playwright.config.ts --list
npx playwright test --config rma-dispatch.config.ts --list
npx playwright test --config seeded.config.ts --list
```

Run the read-only seeded browser checks against an already prepared local target (existing frontend on 3000 with `/api` proxy to 4000):

```bash
cd e2e
SEEDED_E2E_TARGET=local npx playwright test --config seeded.config.ts
```

This acknowledgement does not create or validate a database sandbox by itself. Verify the running backend target first. The URL guard only restricts HTTP access to loopback; it cannot establish which database that backend uses. The existing seed account mapping must match the prepared target, with its linked Driver profile and expected default grants.

Execute browser suites only after the existing frontend/backend have been pointed at and verified against the designated disposable fixture target. Do not launch additional dev servers. Do not run `db:reset`, `prisma migrate reset`, UAT/staging resets or seed commands against the shared/business database as a test prerequisite. PostgreSQL opt-in suites use `PERMISSION_TEST_DATABASE_URL`, `RMA_DISPATCH_TEST_DATABASE_URL` and `SEED_TEST_DATABASE_URL`; leave them unset when no designated target exists and report their skips. The RMA PostgreSQL suite creates/migrates/drops its own additional database and therefore requires suitable local disposable-database privileges.

For every verification run record: revision/working-tree state, command, permission mode, fixture, database/storage/provider type, passed/failed/skipped counts, browser viewport when relevant, and any untested handoff. Do not place connection strings, session cookies, secrets or actual provider credentials in the report.
